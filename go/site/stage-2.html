JS 对照重点

JS 对照

slice ≈ JS Array，但有 len/cap 两把尺；append 可能更换底层数组，两个切片共享底层数组时改一个另一个跟着变（JS 数组赋值是引用，永远「同一个」数组）。

map ≈ JS object/Map，但遍历顺序故意随机（JS object 遍历顺序有规则）、key 必须可比较。判断 key 存在要用 v, ok := m[k] 双返回值，不能像 JS 那样 if (m[k]) 真值判断——Go 里 0 值也是合法存在的值。

struct ≈ JS object + class 字段声明的合体，但赋值即拷贝（值语义）——JS 里对象赋值全是引用，这是从 JS 转 Go 最容易踩的坑。

指针是 JS 完全没有的概念：重点讲「变量的地址」、为什么方法常定义在 *T 上（改自身 vs 改副本）。

第一课 · 数组与切片

覆盖 ch15（数组）、ch18（切片）。练习落在 code/02-slice/。

1. 数组：定长的原始人

var arr [3]int            // 长度写进类型！[3]int 和 [4]int 是两个不同类型
arr[0] = 1
nums := [3]int{1, 2, 3}   // 字面量初始化
auto := [...]int{1, 2, 3} // 让编译器自己数

两个关键认知：① 数组是值类型——赋值、传参都是整份拷贝；② 实际工程里几乎不直接用数组，它是切片的底料。你 99% 的场景写的都是切片。

2. 切片：Go 版的 Array

s := []int{1, 2, 3}        // 不写长度 = 切片
s = append(s, 4)           // 追加（注意：必须接住返回值！）
sub := s[1:3]              // 截取，下标含头不含尾

切片的本体是一个三字段结构：指向底层数组的指针 + len（装了几个）+ cap（底层数组总共能装几个）。cap 不够时 append 会换一个更大的底层数组搬家。

s := make([]int, 0, 10)    // 预分配：len=0，cap=10（工程惯例，省去反复搬家）

3. JS 对照

JS 对照

相同点：动态长度、append ≈ push、下标访问、都能遍历。

不同点：JS 数组赋值 = 复制同一个引用（两个变量是同一个数组）；Go 切片赋值 = 拷贝「指针+len+cap」三字段——两个切片共享同一份底层数据，但 len/cap 各自独立。

易踩坑 ×3：

① append 必须接住：s = append(s, 4)——忘了接住 = 白加（值语义的第一次惩罚）；

② 截取是共享不是拷贝：sub := s[1:3]; sub[0] = 99 会改掉 s[1]！JS 的 arr.slice(1,3) 返回新数组，Go 的 s[1:3] 只是开了个看同一块内存的新窗口；

③ append 搬家后共享断开：对 sub append 触发搬家后，sub 与 s 各自为政。

第二课 · map 与 range

覆盖 ch20（Map）、ch19（Range）。练习落在 code/03-map/。

1. map 基础四式

m := map[string]int{"a": 1, "b": 2}  // 字面量
m["c"] = 3          // 增 / 改
v := m["a"]         // 查
delete(m, "b")      // 删

n := make(map[string]int)  // 空映射
var nilM map[string]int    // ⚠️ nil map：只读安全，写入直接 panic

key 必须是可比较类型（string/int/bool 可以；slice/map/函数不行）。

2. JS 对照

JS 对照

相同点：键值对、动态增删、都是引用类型（赋值即共享）。

不同点：

① 取不存在的 key：JS 给 undefined，所以 if (!m[k]) 能用；Go 给零值（int→0、string→""），m["x"] == 0 分不清「不存在」还是「存在且值为 0」→ 必须用双返回值 v, ok := m["x"]。

② 遍历顺序：JS object 有规则顺序；Go 故意每次随机（运行时洗牌，逼你不依赖顺序写代码）。

③ key 类型：JS 只能 string/Symbol；Go 任意可比较类型。

易踩坑 ×2：nil map 写入 panic（var m map[string]int; m["a"]=1 → panic）——Go 惯例是 make 或字面量起手；nil map 读是安全的（返回零值），只有写炸。

3. for range 全家福

for k, v := range m { }      // map：键、值
for i, v := range s { }      // slice：下标、值
for i := range s { }         // 只要下标
for _, v := range s { }      // 只要值
for i, c := range "中国" { }  // string：字节下标 + rune（i 是 0,3 —— 跳着走！）
JS 对照

JS 的 for-of（拿值）+ for-in（拿 key）两个语法，Go 合成一个 range；不要的返回值用 _ 丢。易踩坑：range string 的 i 是字节位置不是字符序号——第一课 len([]rune) 的姊妹坑。

第三课 · 结构体 struct

覆盖 ch17（结构体）。练习落在 code/04-struct/。这一课是「读 back 代码」的最大门槛——值语义 + tag + 嵌入。

1. struct 基础

type Site struct {
    SiteID    string
    OrgID     string
    Tags      []string
    CreatedAt int64
}

s1 := Site{SiteID: "s1", OrgID: "o1"}  // ① 字段名初始化（推荐，顺序无关）
s2 := Site{"s1", "o1", nil, 0}         // ② 按顺序（不推荐，加字段就崩）
s3 := &Site{SiteID: "s1"}            // ③ 指针初始化（下节课主角）
var s4 Site                            // ④ 零值
s4.SiteID = "s4"

2. JS 对照 · 值语义大考

JS 对照

相同点：字段集合 ≈ JS object 字面量。

不同点：struct 赋值是整份拷贝（值类型！）；JS object 赋值是引用。

a := Site{SiteID: "1"}
b := a              // 整份拷贝
b.SiteID = "2"
// a.SiteID 还是 "1" —— JS 里 a、b 是同一个对象，a.SiteID 也变 "2"

易踩坑 ×2：想共享？用指针 b := &a（下节课主角）；函数传 struct 也是拷贝——大 struct 传参用指针（性能 + 改动原值）。

3. tag：struct 的元数据（back 高频）

type Site struct {
    SiteID string `json:"site_id" gorm:"column:site_id;primaryKey"`
}

反引号包裹的字符串 = 编译器无视、运行时反射读取的「标签」。json 序列化按 tag 重命名键、gorm ORM 按 tag 映射数据库列。这是 back 项目天天写的格式。

JS 对照

JS 没有原生 tag——靠装饰器或手写映射函数；Go 的 tag 是语言内置的元数据通道，第三方库（gorm/gin/validate）全靠它读配置。

4. 嵌入（embedding）—— Go 的"组合复用"

type Base struct {
    CreatedAt int64
    UpdatedAt int64
}
type Site struct {
    Base              // 匿名嵌入：Site 直接拥有 Base 的字段
    SiteID string
}

s := Site{SiteID: "1"}
s.CreatedAt = 123    // 直接访问，像继承

Go 刻意没有 class extends，靠嵌入复用。runoob ch30 叫「继承」，本质是组合——下下节课讲方法时还会回来：嵌入类型的方法也会被「提升」到外层。

5. back 真实代码 · entity/site.go 全文精读

back 真实代码

smb_server/internal/model/entity/site.go——以后天天写的格式：

type Site struct {
    SiteID    string         `json:"site_id" gorm:"column:site_id;type:varchar(64);primaryKey;not null"`
    OrgID     string         `json:"org_id" gorm:"column:org_id;type:varchar(64);not null;index"`
    Tags      pq.StringArray `json:"tags" gorm:"column:tags;type:text[];default:'{}'"`
    Address   SiteAddress    `json:"address" gorm:"embedded"`
    CreatedAt int64          `json:"created_at" gorm:"not null;autoCreateTime:milli"`
}
func (Site) TableName() string { return "sites" }

逐字段拆解：

  • json tag → API 出参键名（site_id 而非 SiteID）
  • gorm tag → 数据库列名、类型、约束（primaryKey / not null / index）
  • pq.StringArray → postgres 数组类型的自定义类型别名（自定义类型也能做字段）
  • Address SiteAddress gorm:"embedded" → 嵌入结构，地址字段展平进 sites 表
  • CreatedAt int64 gorm:"autoCreateTime:milli" → 毫秒时间戳自动填充
  • TableName() → ORM 表名映射（这是个方法，下下节课主角）

结论：back 的「实体类」= Go struct + 双 tag（json + gorm）。

第四课 · 指针与类型转换 讲义就绪 · 未开课

覆盖 ch16（指针）、ch22（类型转换）。练习落在 code/05-pointer/。前三课埋的 &s[0]、&Site{}、&service.UpdateSiteRequest{} 在这里全部收口。

1. 指针 = 存「变量地址」的变量

a := 42
p := &a          // & 取地址：p 的类型是 *int
fmt.Println(p)   // 0xc000012345（地址）
fmt.Println(*p)  // 42 —— * 解引用：顺着地址取值
*p = 100         // 顺着地址改值 —— a 变成 100
fmt.Println(a)   // 100

两个符号记牢：& 取地址（变量 → 指针）、* 解引用（指针 → 变量）。指针的零值是 nil；Go 没有指针运算（C 的 p++ 不存在）——安全但少了一份底层自由。

2. JS 对照 · 为什么需要指针

JS 对照

JS 没有指针，因为 JS 的 object 赋值、传参天然就是「传引用」——你在 JS 里从来没有「拷贝了一个对象」的烦恼（要拷贝还得手写 structuredClone）。

Go 的 struct 是值类型（上节课的大考），想跨函数改动同一个 struct，就得把它的地址传过去：func update(s *Site) { s.SiteID = "x" }。指针是 Go 里「共享可变数据」的显式通道——谁拿了指针一目了然，不像 JS 引用满天飞。

易踩坑 ×2：① nil 指针解引用直接 panic，用前判 nil；② 值接收者方法里改字段改的是副本（阶段 3 方法课细讲）。

3. 类型转换：没有隐式，全家显式

f := 3.14
i := int(f)              // 截断小数 → 3（不是四舍五入！）

s := "中国"
b := []byte(s)           // string → 字节切片（len 3）
r := []rune(s)           // string → 码点切片（len 1）

n, err := strconv.Atoi("65")     // 文本 → int（可能失败 → 双返回值！）
str := strconv.Itoa(65)          // int → 文本

数字↔文本必走 strconv（还记得 string(65)="A" 的坑吗）；string↔[]byte/[]rune 是编码层转换。
