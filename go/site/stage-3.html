JS 对照重点

JS 对照

interface 隐式实现 = 编译期的鸭子类型：JS 天生鸭子（能调就是有），Go 不写 implements、方法集匹配就算实现——但编译器帮你把关。

if err != nil vs try/catch/throw：Go 没有异常、错误是普通返回值，错误必须当场处理或显式上抛（return err），不会像 JS 那样漏写 catch 炸到全局。

组合复用 vs class extends：Go 刻意没有类继承，靠「嵌入」组合。

泛型 [T any] vs JS 动态类型：JS 靠运行时灵活，Go 靠编译期泛型保证类型安全。

第一课 · 方法与组合 讲义就绪 · 未开课

方法（教程散见）+ ch30「继承」＝组合。练习落在 code/06-method-interface/（与接口课共用）。

1. 方法：挂在类型上的函数

type Device struct {
    Name  string
    Price float64
}

//              ↓ 接收者：这个方法属于谁
func (d Device) String() string {
    return fmt.Sprintf("%s($%.2f)", d.Name, d.Price)
}

d := Device{Name: "AP", Price: 99}
fmt.Println(d.String())   // 甚至直接 fmt.Println(d) —— String 方法会被自动调用！

2. 值接收者 vs 指针接收者

func (d Device) Rename1(n string)  { d.Name = n }   // 值接收者：改副本，白改
func (d *Device) Rename2(n string) { d.Name = n }  // 指针接收者：改原值，生效

选择惯例（满足任一条用 *T）：① 方法要修改对象状态；② struct 很大（拷贝浪费）；③ 一个类型里只要有一个方法用了 *T，其余全部跟随保持一致。

JS 对照

相同点：d.String() 的调用写法和 JS 的 d.toString() 一样。

不同点：JS 方法定义在 class/object 内部；Go 方法写在 struct 外面，靠接收者 (d Device) 声明归属——所以甚至能给任意类型（int 别名、string）挂方法。值/指针接收者的区分 JS 不存在（this 永远指向对象本身），Go 必须显式选择「改副本还是改原值」——阶段 2 值语义的延续。

3. 嵌入的方法提升（ch30 组合收口）

type Base struct{ ID int }
func (b Base) Describe() string { return fmt.Sprintf("id=%d", b.ID) }

type Device struct {
    Base                     // 嵌入
    Name string
}

d := Device{Name: "AP"}
fmt.Println(d.Describe())    // Base 的方法被"提升"，d 直接调用——像继承

runoob ch30 叫「继承」，本质是组合：Device 拥有一个 Base，编译器把 d.Describe() 糖译成 d.Base.Describe()。没有父类、没有 override、没有多态链——需要多态时用接口（下节课）。

4. back 真实代码

back 真实代码 ×2

值接收者——entity（只读，返回表名）：

func (Site) TableName() string { return "sites" }

指针接收者——controller（惯例统一 *T）：

func (sc *SiteController) UpdateSite(g *gin.Context) { ... }

再如 func (e *SecurityError) Error() string（阶段 1 见过的安全错误类型）。

第二课 · 接口与类型断言 讲义就绪 · 未开课

覆盖 ch23（接口）、ch29（类型断言）。练习并入 code/06-method-interface/。

1. 接口 = 方法签名的集合，隐式实现

type Describer interface {
    Describe() string
}

// Device 有 Describe() 方法 → 它自动实现 Describer（不用写 implements！）
var x Describer = Device{...}
fmt.Println(x.Describe())

隐式实现是 Go 接口的全部魔法：类型只要有接口要求的全部方法就算实现——定义方和实现方互相不需要知道对方存在。

2. 空接口 any 与类型断言

func show(v any) {                // any = interface{} 别名：什么都能装
    if s, ok := v.(string); ok {   // 类型断言：v 是 string 吗？
        fmt.Println("字符串:", s)
    }
}

switch x := v.(type) {            // 类型 switch：多类型分支
case string:
case int:
}

3. JS 对照

JS 对照

interface 隐式实现 = 编译期的鸭子类型。JS 天生鸭子（能调 .Describe() 就算能描述），运行时才发现没有就 TypeError；Go 同样不看声明只看方法，但编译期就检查方法集齐不齐——鸭子类型的灵活性 + 静态类型的安全性。

易踩坑 ×2：① 接口变量装着 nil 指针时 iface != nil 可能为 true（经典面试题，先知道有这个坑）；② 接口越小越好——Go 惯例一两个方法（io.Reader 只有一个）。

第三课 · 错误处理 讲义就绪 · 未开课

覆盖 ch25。练习落在 code/07-error/。back 最高频代码模式的正体。

1. error 只是个接口

type error interface { Error() string }

err := errors.New("boom")
err2 := fmt.Errorf("site %s not found", "s1")   // 带格式化

q, err := strconv.Atoi("abc")
if err != nil {          // ← 每天写 100 遍的姿势
    return err           // 处理不了就往上传
}

2. 错误包装与判定

err := fmt.Errorf("update site: %w", rawErr)   // %w 包装，保留错误链
errors.Is(err, ErrNotFound)                    // 链上有没有 ErrNotFound？
var myErr *MyError
errors.As(err, &myErr)                        // 链上能不能取出 *MyError？

3. JS 对照

JS 对照

try/catch/throw vs if err != nil：JS 异常沿调用栈向上炸，漏写 catch 就全局崩；Go 错误是普通返回值，错误流向清晰可见、永远不会「逃逸」——代价是每层都要显式处理。

panic 不是 throw：panic 留给「程序 bug / 不可能状态」（越界、nil 解引用），不做业务错误通道；业务错误 100% 走 error 返回值。

4. back 真实代码 · 错误的三层工程化

back 真实代码

自定义错误类型实现 error 接口——errcode 包（阶段 1 见过的常量们的方法版）：

type ErrCode int64
func (e ErrCode) Error() string {          // 挂上 Error() → ErrCode 就是 error
    return fmt.Sprintf("E%v: %v", int64(e), e.String())
}

controller 的三段式（每天写的模式）：

if err := g.BindJSON(req); err != nil {
    sc.logger.Errorf(...)
    pkg.RetJSON(g, errcode.ParamBindError, nil)   // 错误 → 统一错误码响应
    return
}

errcode/error.go 顶部注释还规定了各层错误怎么流转（repo 层 NotFound、service 层 wrap、controller 层转 ErrCode）——错误分层是真实项目的核心纪律。

第四课 · 泛型 + 递归 + 正则 讲义就绪 · 未开课

覆盖 ch24（泛型）、ch21（递归）、ch28（正则）。练习落在 code/08-generics/。

1. 泛型：类型参数

func Map[T, U any](in []T, f func(T) U) []U {   // 类型参数 T、U
    out := make([]U, 0, len(in))
    for _, v := range in {
        out = append(out, f(v))
    }
    return out
}
names := Map(devices, func(d Device) string { return d.Name })

约束不只是 any：[T comparable]（可比较）、[T int | float64]（联合类型）。

JS 对照

JS 的 map 天生泛型（动态类型白送），代价是无编译期保护；Go 1.18 前只能 interface{} + 断言（运行时才炸），泛型把「一份逻辑多种类型」拿到编译期。易踩坑：泛型不是日常工具——基础库（如 gobase）用它，业务代码 90% 场景具体类型就够。

2. 递归（ch21）与正则（ch28）

func factorial(n int) int {        // 递归与 JS 无差异（无尾递归优化，深递归炸栈）
    if n <= 1 { return 1 }
    return n * factorial(n-1)
}

re := regexp.MustCompile(`^\d{4}-\d{2}-\d{2}$`)   // Must* 失败直接 panic，用于启动期
re.MatchString("2026-09-09")                      // true

正则注意：Go 用 RE2 引擎——不支持反向引用/环视（\1、(?=...)），但保证线性时间。从 JS 迁移正则先查这条。
