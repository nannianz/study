第一课 · 方法与组合 已完成 · 2026-09-14 验收

方法（教程散见）+ ch30「继承」＝组合。练习落在 code/06-method-interface/（与接口课共用）。

1. 方法：挂在类型上的函数

JS 的方法住在对象里（class 花括号内、靠 this 寻址）；Go 的 struct 只装数据，方法写在 struct 外面，用接收者语法「挂」上去——归属类型而非某个实例： 

type Device struct {
    Name  string
    Price float64
}

//              ↓ 接收者：这个方法属于谁（= JS 的 this，但有名字、有类型、编译期定死）
func (d Device) String() string {
    return fmt.Sprintf("%s($%.2f)", d.Name, d.Price)
}

d := Device{Name: "AP", Price: 99}
fmt.Println(d)          // AP($99.00) —— String 被自动调用（见 §3 Stringer）

本质：方法就是「第一个参数固定为本类型」的普通函数——d.String() 在编译器眼里即 String(d)。任何 Device 变量自动拥有它；string/int 等没有挂过方法的类型就没有。本地定义的类型（含 type Celsius float64 这种别名）都能挂方法，内置类型本身不行。

2. 值接收者 vs 指针接收者 + 方法集规则

func (d Device) RenameByValue(n string) { d.Name = n }   // 值接收者：改副本，外部不变
func (d *Device) RenameByPtr(n string)  { d.Name = n }  // 指针接收者：改本体，外部生效

d := Device{Name: "phone"}
d.RenameByValue("pad"); fmt.Println(d)  // phone  ← 没变
d.RenameByPtr("pad");   fmt.Println(d)  // pad    ← 变了

选择惯例（满足任一条用 *T）：① 方法要修改对象状态；② struct 很大（拷贝浪费）；③ 一个类型里只要有一个方法用了 *T，其余全部跟随保持一致。

方法集规则（易混点，两套规则别搞混）：

String()/方法定义在 值变量 d := Device{} 指针变量 d := &Device{}
值接收者 (d Device) ✅ 直接调 / ✅ 接口匹配 ✅ 直接调 / ✅ 接口匹配
指针接收者 (d *Device) ✅ 直接调（语法糖补 &d）/ ❌ 接口不匹配 ✅ 直接调 / ✅ 接口匹配

口诀：值接收者人人可调；指针接收者接口匹配只有指针行。编译器能从值安全取地址（(&d).Rename()），但不能从指针反解值自动调（(*d) 有 nil 风险）。这就是「String 定义成 *Device、Println(d 值) 却打出 {phone}」翻车组的全部原因。

JS 对照

相同点：d.String() 的调用写法和 JS 的 d.toString() 一样。

不同点：JS 方法定义在 class/object 内部；Go 方法写在 struct 外面，靠接收者 (d Device) 声明归属——所以甚至能给任意类型（int 别名、string）挂方法。值/指针接收者的区分 JS 不存在（this 永远指向对象本身），Go 必须显式选择「改副本还是改原值」——阶段 2 值语义的延续。

3. Stringer：fmt 的约定接口（隐式接口初体验）

String() string 不是普通方法——fmt 包约定（fmt.Stringer）：打印时自动优先调它。你没 import 任何接口、没注册任何东西，fmt 靠「方法签名匹配」认下你——隐式实现的第一次亲身接触（第二课正题）。

func (d Device) String() string { return d.Name }      // 值接收者版

d  := Device{Name: "phone"}
dp := &Device{Name: "phone"}
fmt.Println(d)   // phone   ← 值接收者：值、指针都匹配 Stringer
fmt.Println(dp)  // phone

// 翻车组：把 String 改成指针接收者后——
func (d *Device) String() string { return d.Name }
fmt.Println(d)   // {phone}  ← 值变量的方法集里没有指针方法 → Stringer 匹配失败，退回原始格式
fmt.Println(dp)  // phone    ← 指针变量正常

4. 嵌入：字段提升 + 方法提升 + 遮蔽（完整版）

type Base struct{ ID int }
func (b Base) Describe() string { return fmt.Sprintf("ID: %d", b.ID) }

type Device struct {
    Name string
    Base                     // 匿名嵌入：只写类型不写字段名
}
func (d Device) String() string {                         // Stringer：外层方法可摸提升字段
    return fmt.Sprintf("%s(ID:%d)", d.Name, d.ID)          // d.ID 即 d.Base.ID —— 外摸内 ✓
}
func (d Device) RenameByValue(n string) { d.Name = n }
func (d *Device) RenameByPtr(n string)  { d.Name = n }
func (d Device) Describe() string {                       // 遮蔽：外层同名盖住内层
    return "Device:" + d.Base.Describe()                   // Go 无 super，调内层版必须显式写全
}

func main() {
    d := Device{Name: "phone", Base: Base{ID: 7}}  // ① 嵌入字段用「类型名」当字段名初始化

    fmt.Println(d.Name)     // phone        ② 字段提升：读
    fmt.Println(d.ID)       // 7
    d.ID = 8                //               字段提升：写
    fmt.Println(d.Base.ID)  // 8            ← d.ID 和 d.Base.ID 是同一个格子

    fmt.Println(d.Base.Describe()) // ID: 8        ③ 方法提升：内层原版还在
    fmt.Println(d.Describe())      // Device:ID: 8  ← 外层遮蔽版生效

    fmt.Println(d)                 // phone(ID:8)    ④ Stringer 自动调用

    d.RenameByValue("pad")
    fmt.Println(d)                 // phone(ID:8)    ⑤ 值接收者：没变
    d.RenameByPtr("pad")
    fmt.Println(d)                 // pad(ID:8)      指针接收者：变了
}

四个关键认知：

  • 匿不匿名差之千里：写成 Extra Base（起名字）后，d.ID、d.Describe() 全部失效，必须 d.Extra.ID——只有匿名嵌入才有提升。
  • 遮蔽 ≠ 重写：外层同名方法只是盖住内层，两个方法同时活着，d.Base.Describe() 随时能调内层版；没有 super 关键字。
  • 方向性：外层方法摸内层提升字段天经地义；内层方法摸外层字段编译不过——Base 的世界里没有 Name。嵌入是 has-a（拥有），不是 is-a（继承）。
  • runoob ch30 叫「继承」，本质是组合：d.Describe() 被糖译成 d.Base.Describe()。没有父类、没有多态链——需要多态用接口（下节课）。

第二课 · 接口与类型断言 已完成 · 2026-09-16 验收

覆盖 ch23（接口）、ch29（类型断言）。练习并入 code/06-method-interface/。

1. 接口 = 方法签名的集合，隐式实现（完整版）

type Describer interface {
    Describe() string
}

type Device struct{ Name string }
func (d Device) Describe() string { return "设备:" + d.Name }   // ← 不写 implements！

type Org struct{ Name string }
func (o Org) Describe() string { return "组织:" + o.Name }      // ← 也不写

func main() {
    var x Describer = Device{Name: "AP-1"}  // Device 方法集齐了 → 自动实现 Describer
    fmt.Println(x.Describe())               // 设备:AP-1

    x = Org{Name: "华东"}                    // 同一个接口变量可以换装
    fmt.Println(x.Describe())               // 组织:华东

    list := []Describer{Device{Name: "AP-1"}, Org{Name: "华东"}}  // 混装 → 多态
    for _, v := range list {
        fmt.Println(v.Describe())           // 设备:AP-1 / 组织:华东
    }
}

隐式实现是 Go 接口的全部魔法：类型只要有接口要求的全部方法就算实现——定义方和实现方互相不需要知道对方存在（Describer 先写后写都行，Device 在别的包也行）。接口变量是个「盒子」：装什么类型就表现什么行为，这正是第一课 Stringer 的原理——fmt 只管「有没有 String()」，不关心你是谁。

2. 方法集决定谁能装进接口（第一课规则表的兑现）

func (d Device) Describe() string  { ... }   // 值接收者
func (o *Org) Describe() string   { ... }   // 指针接收者

var x Describer
x = Device{Name: "AP-1"}    // ✅ 值接收者：值、指针都能装
x = &Device{Name: "AP-1"}   // ✅
x = &Org{Name: "华东"}      // ✅ 指针接收者：指针能装
x = Org{Name: "华东"}        // ❌ 编译错！Org 的方法集在 *Org 上，值的方法集里没有 Describe

第一课方法集表的「接口匹配」列在此兑现：值接收者人人可装；指针接收者只有指针能装。工程含义：想要接口装值，方法就得定义成值接收者——但这与「大 struct / 要改状态用 *T」的惯例冲突，所以 back 里实体方法几乎全是 *T，接口变量装的也全是指针（Controller 的实现者都是 *SiteController）。

3. 空接口 any 与类型断言（comma-ok 家族）

func show(v any) {                    // any = interface{} 别名：什么都能装
    if s, ok := v.(string); ok {       // 类型断言：v 里装的是 string 吗？
        fmt.Println("字符串:", s)      // 装的不是 → ok=false，不会 panic
    }
}

show("hi")          // 字符串: hi
show(42)            // （静默跳过）

switch x := v.(type) {                // 类型 switch：断言的批量版
case string:
    fmt.Println("字符串", len(x))       // 每个 case 里 x 自动是该类型
case int:
    fmt.Println("整数", x+1)
case Device:
    fmt.Println("设备", x.Name)
default:
    fmt.Println("其他")
}

comma-ok 三兄弟（同一套「值 + 真相」双返回值格式）：map 判存在 v, ok := m[k]（阶段 2 已学）、类型断言 v, ok := x.(T)（本课）、channel 接收 v, ok := <-ch（阶段 4）。学会一个等于学会三个。

第三课 · 错误处理 已完成 · 2026-09-28 验收

1. error 只是个接口（完整版）

type error interface { Error() string }   // 标准库唯一内置的接口，就一个方法

err := errors.New("boom")                        // 最简单的错误
err2 := fmt.Errorf("site %s not found", "s1")    // 带格式化的错误

n, err := strconv.Atoi("abc")   // 阶段 2 转换实验的伏笔：解析失败返回 (0, err)
if err != nil {                 // ← 每天写 100 遍的姿势
    fmt.Println(err)            // strconv.Atoi: parsing "abc": invalid syntax
    return                      // 处理不了就 return err 往上传
}
fmt.Println(n)                  // 只有 err == nil 才走到这，n 才可信

错误是普通返回值，不是异常：函数签名 (result, error) 把「可能失败」写进类型里，调用方看一眼签名就知道要不要处理、编译器盯着你不许漏（不接 err 编译不过，`_` 显式丢弃才行）。

2. 自定义错误 + 错误链（完整版）

// ① 自定义错误类型：挂上 Error() 方法就是 error（隐式接口的又一次应用）
type NotFoundError struct{ SiteID string }
func (e *NotFoundError) Error() string {
    return "site not found: " + e.SiteID
}

// ② 模拟三层调用：每层用 %w 包装，保留错误链
func loadFromDB(id string) error {
    return &NotFoundError{SiteID: id}            // 最底层：原始错误
}
func loadSite(id string) error {
    if err := loadFromDB(id); err != nil {
        return fmt.Errorf("load site %s: %w", id, err)   // %w 包装（不是 %v！）
    }
    return nil
}
func handleRequest(id string) error {
    if err := loadSite(id); err != nil {
        return fmt.Errorf("handle request: %w", err)     // 再包一层
    }
    return nil
}

func main() {
    err := handleRequest("s1")
    fmt.Println(err)                        // handle request: load site s1: site not found: s1
                                            //   ← 整条链像洋葱一样全打出来

    var nf *NotFoundError
    fmt.Println(errors.As(err, &nf))        // true  ← 链上能取出 *NotFoundError
    fmt.Println(nf.SiteID)                  // s1    ← 取出后还能读字段（断言进阶版）

    fmt.Println(errors.Is(err, &NotFoundError{}))  // false：Is 比的是同一个实例
}

三个要点：① %w 包装、%v 断链——用 %v 也能打出一样的文字，但错误链断了，Is/As 全部失效；② errors.As 是「带类型的断言」——沿链找出目标类型并取出（comma-ok 的错误版）；③ errors.Is 比身份——适合哨兵错误（var ErrNotFound = errors.New(...) 单一实例比较）。

3. JS 对照

JS 对照

try/catch/throw vs if err != nil：JS 异常沿调用栈向上炸，漏写 catch 就全局崩，而且看函数签名完全不知道会不会 throw；Go 错误是普通返回值，错误流向清晰可见、永远不会「逃逸」——代价是每层都要显式处理。错误信息打全链 ≈ JS 的 error.stack，但 Go 是每层手动包的、信息可控。

panic 不是 throw：panic 留给「程序 bug / 不可能状态」（越界、nil 解引用、nil map 写入——阶段 2 亲手 panic 过的那些），不做业务错误通道；业务错误 100% 走 error 返回值。易踩坑：从 JS 过来用 throw 的习惯直接 panic——panic 不被 recover 就整个进程挂掉，网管后台几千台设备在线时这是事故。

1. 泛型：类型参数（完整版）

// [T, U any] 是类型参数列表——调用时才决定 T、U 是什么
func Map[T, U any](in []T, f func(T) U) []U {
    out := make([]U, 0, len(in))     // 预分配：阶段 2 的 cap 优化知识复用
    for _, v := range in {
        out = append(out, f(v))
    }
    return out
}

func Filter[T any](in []T, keep func(T) bool) []T {
    out := make([]T, 0, len(in))
    for _, v := range in {
        if keep(v) { out = append(out, v) }
    }
    return out
}

func Contains[T comparable](xs []T, target T) bool {   // comparable 约束：能用 == 比较
    for _, v := range xs {
        if v == target { return true }
    }
    return false
}

type Device struct{ Name string; APCount int }

func main() {
    devices := []Device{{"AP-1", 5}, {"AP-2", 0}, {"AP-3", 12}}
    names  := Map(devices, func(d Device) string { return d.Name })   // []Device → []string
    online := Filter(devices, func(d Device) bool { return d.APCount > 0 })
    fmt.Println(names)                    // [AP-1 AP-2 AP-3]
    fmt.Println(online)                   // [{AP-1 5} {AP-3 12}]
    fmt.Println(Contains(names, "AP-2"))  // true
}

约束不只是 any：[T comparable]（可比较，能用 == / map key）、[T int | float64]（联合类型，限数值）。对照 JS：arr.map(f) 天生「泛型」（动态类型白送），代价是无编译期保护；Go 1.18 前只能 interface{} + 断言（运行时才炸），泛型把「一份逻辑多种类型」拿到编译期——Map(devices, f) 传错回调参数类型编译期就报。易踩坑：泛型不是日常工具——基础库（如 gobase）用它，业务代码 90% 场景具体类型就够。

2. 递归（ch21）与正则（ch28）

func factorial(n int) int {        // 递归与 JS 无差异（无尾递归优化，深递归炸栈）
    if n <= 1 { return 1 }          // 终止条件必须有，否则无限递归 panic
    return n * factorial(n-1)
}
fmt.Println(factorial(5))          // 120

re := regexp.MustCompile(`^(\d{4})-(\d{2})-(\d{2})$`)   // Must* 失败直接 panic，用于启动期
fmt.Println(re.MatchString("2026-09-09"))               // true
m := re.FindStringSubmatch("2026-09-09")                // 捕获组：整个匹配 + 各组
fmt.Println(m[1], m[2], m[3])                           // 2026 09 09

正则注意：Go 用 RE2 引擎——不支持反向引用/环视（\1、(?=...)），但保证线性时间（不会灾难性回溯）。从 JS 迁移正则先查这条。
