JS 对照

静态类型 vs 动态类型：Go 编译期就报类型错误，JS 运行时才知道；写 Go 时「先想类型再写代码」。

switch 默认 break；case 不需要是常量。

多返回值 vs JS 返回数组再解构：Go 的 (result, err) 是语言级能力。

没有默认参数；有可变参数 ...（≈ JS rest 参数）。

第一课 · 变量与基本类型

覆盖 ch6（基础语法）、ch7（数据类型）、ch8（变量）。练习落在 code/02-types/。

0. 先换挡：从「动态」到「静态」

JS 里变量是个盒子，想装什么装什么：

let a = 1
a = "hello"   // 没问题，类型运行时才管

Go 里变量是个贴了类型标签的盒子，出生那天标签就焊死了：

a := 1
a = "hello"   // 编译直接报错：cannot use "hello" (untyped string) as int

这不是 Go 古板，是它的核心契约：所有类型错误在编译期暴露，跑到线上的代码不会有 undefined is not a function 这类惊喜。在 smb 项目里 Ctrl+S 保存时编辑器秒报错，就是这套机制在干活。

JS 对照 · 行尾分号去哪了（2026-09-02 随堂答疑）

写完一行发现分号「加不上」——是 Trae 的 gopls 保存时自动跑 gofmt 把它删了。对代码零影响：Go 编译器有自动分号插入（ASI）——行尾最后是标识符/字面量/) ] }/++/-- 或 return/break 等关键字时，编译器自动补分号。

JS 也有 ASI，但社区一半人坚持写分号（有 return 换行坑）；Go 反转文化：所有人都不写，gofmt 强制删。

分号真正必需的三处：① for 三段式 for i := 0; i < 10; i++ ② 一行多条语句 a := 1; b := 2 ③ 一行写完 if 体 if ok { do(); return }。

易踩坑：大括号必须跟在行尾。把 { 另起一行（某些 JS 风格），行尾会被自动插分号截断 if → 语法错误。报错长得离谱时先查大括号位置。

1. 声明变量的三种姿势

var name string = "smb"   // ① 完整版：手动写类型
var name2 = "smb"         // ② 省类型：编译器自己推断
name3 := "smb"            // ③ 短声明：声明+推断+赋值三合一，日常 90% 用它
JS 对照

let x = 1 ≈ x := 1——写法几乎一样，但 JS 的 x 以后能换类型，Go 的不能。

:= 只能在函数内部用；包级别（函数外）只能用 var。

:= 是「声明新变量」，给已有变量赋值用 =——两者搞混是新手第一大报错来源。

2. 声明了不用 = 编译错误

Go 的著名洁癖：

x := 1        // 后面没用 x → 编译失败：declared and not used

JS 里声明不用顶多被 ESLint 骂一句，Go 直接不让你编译。目的：杜绝「死变量」，读代码时每个变量都必然有用。

3. 零值（Go 版的 undefined）

JS 变量没赋值是 undefined；Go 里每种类型都有确定的零值，永远不存在 undefined：

var i int       // 0
var s string    // ""（空字符串，不是 null！）
var b bool      // false

4. 基本类型对照表

GoJS备注
stringstring都不可变；但 Go 的 len 数的是字节
boolboolean没有 truthy/falsy！
int / float64numberGo 把整数和浮点分开家
rune无对应一个 Unicode 码点，本质是 int32
byte无对应一个字节，本质是 uint8
易踩坑 ×2

坑 1：没有隐式类型转换。JS 里 1 + 1.5、"1" + 1 随便混（然后喜提 "11"）；Go 里 int 和 float64 相加都要显式转换：float64(i) + 1.5。另埋一颗雷：string(65) 得到的不是 "65" 而是字符 "A"（它把 65 当 Unicode 码点转了），数字转字符串要用 strconv.Itoa(65)。

坑 2：bool 没有 truthy。if 1 { 在 Go 里直接编译错误。JS 面试最爱考的 if("0") 为 true 之类的题，在 Go 里不存在——条件必须是货真价实的 bool。

5. string 与 rune：1.js 的续集

JS 对照

f/1.js 里验证过 JS 的 "中".length === 1（UTF-16 码元数）。Go 这边：

len("中")            // 3 —— UTF-8 字节数（中文每字 3 字节）
len("中国")          // 6
len("a")             // 1
len([]rune("中国"))   // 2 —— 转成码点数组后才是「字符数」

一句话：Go 的 len(string) 永远是字节数，想要「字符数」先转 []rune。JS 的 length 数码元、Go 的 len 数字节——两边都不是人类直觉的「字数」，但 Go 的规则更简单粗暴。

第二课 · 常量、iota 与运算符

覆盖 ch9（常量）、ch10（运算符），并揭晓第一课埋的 string(65)="A" 之坑。

1. const：编译期就定死的值

const Pi = 3.14159
const AppName = "smb"
JS 对照

相同点：都叫 const、都不能重新赋值。

不同点：JS 的 const 是「绑定不可变」——const arr = []; arr.push(1) 完全合法，锁的是变量名与值的指向；Go 的 const 是「值不可变」，且值必须在编译期就能算出来。

易踩坑：JS 里 const x = Date.now() 可以（运行时求值）；Go 里 const x = time.Now().Unix() 直接编译报错——函数调用是运行时行为，const 装不下，得用 var。

2. iota：Go 的枚举器

const 块里的行计数器：第一行为 0，往下每行 +1：

const (
    Monday = iota   // 0
    Tuesday         // 1（省略表达式 = 重复上一行的 iota 表达式）
    Wednesday       // 2
)
JS 对照

JS 没有原生枚举，常见手搓：const Week = { Monday: 0, Tuesday: 1 } 或 TS 的 enum。Go 的 iota 就是官方内置的计数器方案，少写重复的 = 0, = 1, = 2。

易踩坑：iota 只在 const 块里有意义；想跳号用 _ 占位。

4. 运算符：九分像，三个坑

+ - * / % == != < > && || ! 与 JS 基本一致，逻辑运算符同样短路。坑在这三处：

易踩坑 ×3

坑 1：++/-- 是语句不是表达式。x++ 可以；y := x++ 编译报错；也没有 ++x 前缀写法。JS 里 arr[i++] 这类写法到 Go 全部要拆成两行。

坑 2：没有三元运算符 ?:。cond ? a : b 只能老老实实写 if-else。官方理由：嵌套三元是可读性杀手。

坑 3：字符串 + 只能拼字符串。JS 的 "a" + 1 得 "a1"；Go 里 "a" + 1 直接编译报错，要先 strconv.Itoa(1) 转成字符串——Go 不做任何隐式转换，字符串拼接也不例外。

5. 揭晓：string(65) 为什么是 "A"

Go 的类型转换 T(v) 语义是「把 v 的值按 T 类型的含义重新解释」，而 string 遇到整数时的含义是「Unicode 码点 → 字符」（因为 rune 本质就是 int32）：

string(65)          // "A"   —— 65 号码点对应的字符
string(20013)       // "中"  —— 20013 是 "中" 的码点
strconv.Itoa(65)    // "65"  —— 整数 → 十进制文本（人话转换）
strconv.Atoi("65")  // 65    —— 反向：文本 → 整数
JS 对照

JS 的 String(65) 永远给你 "65"（ ToString 规则，总说人话）；Go 的 string(65) 却按码点查表。数字转字符串，无脑用 strconv.Itoa，把 string(数字) 留给「我知道这是码点」的场景。

if 带初始化语句：Go 特色

if v, err := strconv.Atoi("42"); err != nil {
    // 出错分支
} else {
    // v 只在 if/else 块内可见！
}

声明和判断一行搞定，v、err 的作用域被锁在 if 块内——JS 没有这个语法，最接近的写法（const 写在 if 前面）会泄漏作用域。

for 一统天下

for i := 0; i < 10; i++ { }  // 三段式
for x < 10 { }               // 只有条件 = JS 的 while
for { }                       // 什么都没有 = 死循环（配 break）
for i, v := range s { }       // 遍历（阶段 2 细讲）

JS 的 for / while / do-while / for-in / for-of 五个语法，Go 一个 for 全包。

switch：默认 break

switch day {
case 1, 2, 3, 4, 5:          // case 可多值
    fmt.Println("工作日")
default:
    fmt.Println("周末")
}

switch {                     // 无表达式 switch = if-else 链的整齐版
case score >= 90:
    // ...
}

JS 的 switch 不 break 会穿透（经典 bug 源）；Go 反转默认——不穿透，要穿透必须显式写 fallthrough。case 还不要求是常量。

函数：多返回值是语言级能力

func divide(a, b int) (int, error) { ... }   // 返回两个值
q, r := divide(10, 3)
q, _ := divide(10, 3)                        // _ 丢弃不要的

func sum(nums ...int) int { }                // 可变参数 ≈ JS rest
JS 对照

JS 想返回多个值只能返回数组再解构 const [q, err] = divide()，类型不受保护；Go 的多返回值每个位置都有类型。没有默认参数；闭包与匿名函数和 JS 几乎一致。
