排障实录（比计划本身更值钱的三课）

阶段 0 实际执行中踩的三个坑，全部复盘归档。每个都是很多人写半年也未必全遇上的实战知识。

案例一：装完 Go，终端里却「找不到 go」

症状：msi 安装成功，go version 报「不是内部或外部命令」。

根因：环境变量快照。安装器把 C:\Program Files\Go\bin 写进注册表里的系统 PATH，但 PATH 不是实时读取的——每个终端/程序启动时拷贝一份快照，之后永不更新。安装前就开着的终端里，go 命令自然「不存在」。

解法：关掉所有旧终端重开；IDE 要重启整个程序（只关终端标签页没用，托盘图标也要退出）。JS 同学其实早就遇过：装完 Node 不重开终端，node -v 一样报错。

案例二：一台机器，两份 Go

症状：Trae 终端里 go version 是 1.25.9，系统 PowerShell 里是 1.27.0。

根因：Trae 的「AI 装环境」把一份独立 SDK 装到了 C:\Users\admin\sdk\go1.25.9，并注入它自己的集成终端；后来手动 msi 装的 1.27.0 在 C:\Program Files\Go。两份工具链互不知晓。用 nvm 类比：一份是 nvm 装的 node，一份是官网直装版。

解法：删掉 C:\Users\admin\sdk\go1.25.9 与 ~/go/bin/linux_arm64（Trae 留下的怪文件），重启 Trae，全机一份 Go。

案例三：exe「消失」疑云——GOOS/GOARCH 交叉编译幽灵

症状：go run 报 executable file not found in %PATH%；go build 产物无 .exe 后缀、双击/执行都报不是有效程序。最初怀疑杀毒软件（腾讯管家）删临时 exe，实验推翻：build 出的 exe 从未被删。

根因：用户级环境变量被写入 GOOS=linux、GOARCH=arm64（同样是 Trae 装环境留下的）。效果是每一条编译命令都在交叉编译成 Linux ARM64 二进制（file 命令验明：ELF ARM aarch64）。Windows 认不出 Linux 格式，「找不到 exe」其实是「exe 是 Linux 的」。

解法：删掉这两个用户级变量 + 换全新终端验证 go env GOOS GOARCH = windows/amd64。注意：删变量后老终端仍显示旧值——又是案例一的快照机制，第三次交手。

附赠知识：交叉编译是 Go 的招牌能力——一条命令直接打出任意 OS/CPU 架构的可执行文件，不需要目标机工具链。正确用法是命令前缀、单次生效：GOOS=linux GOARCH=arm64 go build。以后给公司 ARM 架构网络设备（AC/交换机）打包 agent 全靠它。

复盘：环境变量的三层心智模型

① 进程快照（改了注册表，老进程不知道）→ ② 用户级变量（HKCU，只影响当前用户，本次事故现场）→ ③ 系统级变量（HKLM，Machine PATH 里躺着 Go 的安装路径）。

go 命令自己的配置也有三层：go env -w 写的文件（~/AppData/Roaming/go/env）→ 环境变量 → 内置默认值。排查「工具行为诡异」时按层剥洋葱。
