JS 对照重点

JS 对照

ES modules vs Go packages：import 路径 = 仓库路径；大写开头 = export（≈ JS 的 export 关键字被命名规范取代）。

go get ≈ npm install；go.mod+go.sum ≈ package.json+lock。

go test vs vitest/jest：无断言库依赖（if got != want { t.Errorf(...) }）、表驱动测试是官方推荐范式。

gofmt/go vet ≈ prettier/eslint，但内置零配置。

第一课 · 包、模块与文件 讲义就绪 · 未开课

1. 大写导出，小写私有

// pkg/mathx/mathx.go —— 注意：包名 = 目录名 = 小写（Go 包名永远小写）
package mathx

var factor = 2          // 小写：仅本包可见（包括下面的内部函数）

func Double(n int) int {   // 大写开头 → 其他包可用（≈ export）
    return n * factor
}

func doubleTwice(n int) int {   // 小写开头 → 仅本包可见
    return double(double(n))
}
func double(n int) int { return n * factor }
// main.go —— 另一个包（package main）
package main

import (
    "fmt"
    "gostudy/pkg/mathx"       // import 路径 = 模块名(go.mod 里的) + 目录路径
)

func main() {
    fmt.Println(mathx.Double(21))     // ✅ 42
    // fmt.Println(mathx.double(21))  // ❌ undefined: mathx.double（小写不可见）
    // fmt.Println(mathx.factor)      // ❌ undefined: mathx.factor
}

常量、类型、结构体字段、方法全部同规则（阶段 2 讲过的 json.Marshal 只认大写字段就是同一条规则）。没有 export 关键字——命名即可见性。调用侧永远带包名前缀 mathx.Double（不能省，Go 没有 JS 那种解构 import）。

2. import 路径与 go mod

import (
    "fmt"                       // 标准库
    "gostudy/pkg/mathx"         // 本模块内：模块名 + 相对路径
    "github.com/gin-gonic/gin"  // 第三方：仓库路径（gin 作为包名使用）
)
go get github.com/x/y@v1.2.3   // 加依赖 ≈ npm install pkg@版本
go mod tidy                    // 按实际 import 清理/补齐依赖表（≈ npm install 的自动版）

internal/ 魔法目录：路径里带 internal 的包只有其父目录树内能 import，外部强行 import 直接编译报错——编译器强制的私有边界。back 的 smb_server/internal 就靠它锁住 controller/service 不被外部引用。

包 = 目录，不是文件（阶段 2 踩过的坑的正式表述）：同目录所有文件的 package 声明必须一致，包内函数互相调用不需要 import——net_scan 的 internal/api 目录 24 个 .go 文件全是 package api，handlers.go 直接调 operation_audit.go 里的函数。

3. 文件读写三件套

data, err := os.ReadFile("config.json")      // 一口读
if err != nil {                              // 文件不存在/没权限——阶段 3 错误处理实战
    log.Fatal(err)
}
err = os.WriteFile("out.txt", data, 0644)    // 一口写

f, err := os.Open("big.log")                 // 大文件：逐行（不整载内存）
if err != nil { log.Fatal(err) }
defer f.Close()                              // 惯例：打开就 defer 关
scanner := bufio.NewScanner(f)
for scanner.Scan() {
    line := scanner.Text()
}

第二课 · 单元测试 讲义就绪 · 未开课

教程外补充（对照 back）。练习落在 code/12-testing/。

1. 测试文件与函数

// device_test.go —— 与被测文件同目录同包，_test.go 后缀（go run 自动忽略它，只有 go test 编译）
func TestDeviceDiscount(t *testing.T) {     // Test 前缀 + 唯一参数 *testing.T
    d := Device{Name: "AP", Price: 100}
    got := d.Discount(0.8)
    if got != 80 {
        t.Errorf("Discount(0.8) = %v, want 80", got)   // 报错但继续跑后续用例
    }
}
go test ./...            # 跑全部测试（≈ vitest run）
go test -run TestDevice  # 只跑一个（≈ vitest -t）
go test -v               # 显示每个用例（≈ vitest --reporter=verbose）
# go test -v 的输出长这样（先见个面）：
=== RUN   TestDeviceDiscount
--- PASS: TestDeviceDiscount (0.00s)
PASS
ok      gostudy/code/12-testing    0.012s

# 故意写错 want 时的失败输出：
--- FAIL: TestDeviceDiscount (0.00s)
    device_test.go:9: Discount(0.8) = 79.9, want 80
FAIL

t.Errorf 记录失败继续跑，t.Fatalf 立即终止本用例——后续断言依赖前面的结果时用 Fatalf（比如响应码都错了，再解析 body 没意义）。

2. 表驱动测试（官方范式）

func TestDiscount(t *testing.T) {
    tests := []struct {           // 匿名 struct 切片当用例表（阶段 2 匿名嵌入的近亲：匿名 struct）
        name  string
        price float64
        ratio float64
        want  float64
    }{
        {"正常8折", 100, 0.8, 80},
        {"零价格", 0, 0.8, 0},
        {"免费", 100, 0, 0},
        {"全价", 100, 1, 100},
        {"超界负数", 100, -0.5, 0},      // 边界与异常一并覆盖
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {     // 子测试：每个用例独立报告
            d := Device{Price: tt.price}
            if got := d.Discount(tt.ratio); got != tt.want {
                t.Errorf("%s: Discount(%v) = %v, want %v", tt.name, tt.ratio, got, tt.want)
            }
        })
    }
}

用例数据与断言逻辑分离：加用例只加一行、失败时按 name 精确定位、-run TestDiscount/零价格 可单跑某个子用例。这是 Go 官方推荐的标准范式，back 全线在用。

3. JS 对照

JS 对照

vitest 的 expect(got).toBe(want) 好写，但那是框架能力；Go testing 包零依赖、零断言库——if + t.Errorf 就是全部（标准库连 assert 都不提供，社区有 testify 但 net_scan 只在个别处用）。表驱动 ≈ test.each([...])；t.Run ≈ describe/it 层级。测试文件与被测代码同目录同包（不是 __tests__/ 分离）——测试可以访问包内小写私有函数，这是刻意的。

back 真实代码 ×2

net_scan 的 Web 层测试——httptest 模拟请求（不用起真服务器）：auth_handlers_test.go 原文风格：

func TestAuthMeReturnsAnonymousWhenNotLoggedIn(t *testing.T) {
    router := newAuthTestRouter(t)                    // 搭测试专用路由（注入测试 repo）

    req := httptest.NewRequest(http.MethodGet, "/api/auth/me", nil)  // 造请求
    resp := httptest.NewRecorder()                    // 造响应 recorder

    router.ServeHTTP(resp, req)                       // 直接调 ServeHTTP——不发网络包

    if resp.Code != http.StatusOK {
        t.Fatalf("expected 200, got %d with body %s", resp.Code, resp.Body.String())
    }
    // 再 json.Unmarshal(resp.Body.Bytes(), &body) 断言字段……
}

表驱动 + httptest 模拟请求 + mock repo 注入 = Go Web 测试标准三件套。smb 的 service 层测试用 gomock 生成的 mock（阶段 5 第一课看过的 go:generate）——接口定义好后 mock 全自动。
