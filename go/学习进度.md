### JS 对照重点

- **静态类型 vs 动态类型**：Go 编译期就报类型错误，JS 运行时才知道；写 Go 时「先想类型再写代码」
- `var` / `const` / `:=` vs `var` / `let` / `const`：`:=` 是「声明+推断类型」的简写，只能用在函数内
- **string 是字节序列**：`len("中")` 是 3（UTF-8 字节数），不是 1；取「字符」要转 `[]rune`。正好接上我在 `f/1.js` 里做的 `"中".length` 实验——JS 的 length 数的是 UTF-16 码元，两边的「长度」都不是直觉上的字符数
- **for 是唯一循环**：JS 的 while / do-while / for-in / for-of 在 Go 里全是 for 的变体
- switch 默认 break（JS 的 fallthrough 反而是例外）、case 不需要是常量
- **函数多返回值** vs JS 返回数组再解构：Go 的 `(result, err)` 是语言级能力
- 没有默认参数；有可变参数 `...`（≈ JS rest 参数）

### JS 对照重点

- **slice ≈ JS Array**，但有 len/cap 两把尺；`append` 可能更换底层数组，两个切片共享底层数组时改一个另一个跟着变（JS 数组赋值是引用，永远「同一个」数组）
- **map ≈ JS object/Map**，但遍历顺序故意随机（JS object 遍历顺序有规则）、key 必须可比较
- **struct ≈ JS object + class 字段声明的合体**，但**赋值即拷贝（值语义）**——JS 里对象赋值全是引用，这是从 JS 转 Go 最容易踩的坑
- **指针是 JS 完全没有的概念**：重点讲「变量的地址」、为什么方法常定义在 `*T` 上（改自身 vs 改副本）

## 阶段 3：方法、接口与错误处理

**目标**：掌握 back 项目最核心的三大代码模式：struct 方法、接口、`if err != nil`。

### 章节 checklist

- [ ] 方法（补充，教程散见）：值接收者 vs 指针接收者

- [ ] 接口（ch23）：定义、隐式实现、空接口 interface{}

- [ ] 继承≈组合（ch30）：嵌入 struct / 嵌入 interface
- [ ] 泛型（ch24）：`[T any]`、约束
- [ ] 错误处理（ch25）：error 接口、自定义错误、errors.Is/As
- [ ] 正则表达式（ch28）

### JS 对照重点

- **interface 隐式实现 = 编译期的鸭子类型**：JS 天生鸭子（能调就是有），Go 不写 implements、方法集匹配就算实现——但编译器帮你把关
- **`if err != nil` vs try/catch/throw**：Go 没有异常、错误是普通返回值，错误必须当场处理或显式上抛（`return err`），不会像 JS 那样漏写 catch 炸到全局
- 组合复用 vs class extends：Go 刻意没有类继承，靠「嵌入」组合
- 泛型 `[T any]` vs JS 动态类型：JS 靠运行时灵活，Go 靠编译期泛型保证类型安全

## 阶段 4：并发

**目标**：理解 goroutine 与 channel，建立「并发要考虑数据竞争」的意识——JS 单线程思维的最大转变。

### 章节 checklist

- [ ] Go 并发（ch26）：goroutine、channel（无缓冲/带缓冲）、遍历与关闭
- [ ] 补充：sync.WaitGroup、sync.Mutex、select（教程较浅，结合 back 补）

### JS 对照重点

- 单线程事件循环 vs 多协程真并行：JS 的 async 是「协作式调度」，goroutine 是抢占式、可跑满多核
- `go func(){...}`() ≈ 触发异步任务，但**通信方式完全不同**：JS 靠 Promise 链/回调取值，Go 靠 channel 传值（值发过去，不是共享变量）
- channel ≈ MessageChannel/消息队列，但有**阻塞语义**：没人收就卡住（这正是 Go 想要的同步点）
- **数据竞争要加锁（Mutex）**——JS 永远不需要锁，这章是思维转变最大的一章
